# 前端国际化（i18n）约定

适用对象：任何修改 `frontend/src` 的开发者或 AI 编程助手。**动手改文案前请先读完本文**，否则容易做出「以为在修 bug、实际在破坏英文模式」的改动。

相关文件：

- `frontend/src/i18n/index.tsx` —— 唯一字典与 `LanguageProvider` / `useLanguage()` / `t()`
- `frontend/src/i18n/__tests__/language.test.tsx` —— 语言切换与取值测试

## 核心机制：key 就是中文原文

本项目的字典方向是 **中文 → 英文**，不是常见的「英文 key → 各语言文案」：

```ts
const englishMessages: Record<string, string> = {
  'AI 作业批改': 'AI Marking',
  题目库: 'Question Library',
  // ACP 批改助手目录(设置页)
  批改助手目录: 'Marking assistant catalog',
  ...
};

const t = useCallback(
  (key: string, fallback?: string) => {
    if (locale === 'zh-CN') return fallback ?? key;   // 中文模式：直接吐回 key，不查表
    return englishMessages[key] ?? fallback ?? key;   // 英文模式：查表，未命中逐级回退
  },
  [locale],
);
```

`locale` 首次访问跟随浏览器语言，用户切换后写入 `localStorage`（键 `ai-marking-locale`）。

由此推出四条必须记住的结论：

| 结论 | 说明 |
|---|---|
| 代码里写 `t('运行配置')`，中文界面显示「运行配置」 | zh-CN 分支根本不查字典，key 本身就是显示文案 |
| **只删字典条目，对中文界面零影响** | 该条目仅在 en-US 下生效；删除后英文模式退回显示中文，中文模式一直没用过它 |
| 中文串没进字典也**不算 bug** | `?? fallback ?? key` 兜底，未命中就原样显示中文 |
| 字典里存在条目 ≠ 有地方在用 | 删 UI 后残留的「死条目」无任何运行时影响，只是英文模式下永远不会被命中 |

## 增删改操作规则

1. **新增文案**：直接在组件里写 `t('中文文案')`，中文模式立刻正确。**只有希望英文模式也显示英文时**，才需要往 `englishMessages` 追加一条。
2. **删除 UI**：同步清掉字典里对应的死条目（保持字典可维护）；但反过来，只删字典条目不会让中文界面变化。
3. **修改文案**：`t()` 里的中文和字典里的 key 必须**同步改**。只改一处会导致英文模式命中失败、静默回退为旧中文，不会报错。
4. **引号规则（语法坑）**：key **含空格或标点必须加引号**，如 `'调整评分面板与 AI 助手宽度'`；纯中文无空格可裸写，如 `调整作业与评分面板宽度`。裸写带空格的 key 会直接编译报错 `Expected ',' or '}'`。**建议一律加引号。**
5. **分节放置**：字典按功能分节，用中文注释标出（如 `// ACP 批改助手目录(设置页)`、`// ACP 对话面板(审阅页右侧)`）。新条目追加到对应分节末尾，不要插到文件开头。
6. **第二参数 `fallback`**：`t(key, fallback)` 在 zh-CN 下**优先返回 fallback**（参见 `ErrorBoundary.tsx`）。用于锁定一个确定的中文串，日常写文案不需要传。
7. **用户业务内容不翻译**：学生文件名、OCR 文本、评分建议与反馈等一律保持原文，不得进字典。

## 常见误判（不要做）

- ❌ 看到「速度模式」「已生效」这类串没进字典，就补一条 —— 它们两种语言下都显示中文，属预期行为。
- ❌ 把 key 统一改成英文标识符（如 `runConfig`）—— 会破坏整个现有体系，且必须重写 500+ 条条目。
- ❌ 在 zh-CN 模式下验证英文文案 —— 永远看不到效果，必须切到 en-US。
- ❌ 改了 `t()` 里的中文却忘了改字典 key，或反之。

## 验证路由（改动后只跑最小集合）

见 [PROJECT.md](../../PROJECT.md) 的「改动域 affected-check 路由」。针对 i18n 的补充：

| 改动类型 | 最小检查 |
|---|---|
| **仅**增删/修改 `englishMessages` 条目，未触碰任何 `t()` 调用点与组件逻辑 | `cd frontend && npm run lint`（可选 `npx tsc -b --noEmit`）。**不必跑全量 `npm run test:run`** |
| 改动了组件里的 `t()` 调用点、`LanguageProvider`、语言切换或 locale 检测 | `npm run lint` + `npm run test:run`，并定向复跑 `npx vitest run src/i18n` |
| 需要肉眼确认英文文案 | 界面切换到 en-US 后检查对应位置 |

为什么字典-only 改动可以免跑全量测试：`i18n/index.tsx` 被几乎所有组件 import，任何全量 `vitest run`（20 文件 / 134 测试，全 jsdom 挂载）都要跑数分钟并打满 CPU；而字典条目在 zh-CN 下**完全不参与取值**，删改它对中文运行时零影响，最坏结果只是英文模式那条回落为中文——不构成功能缺陷。

> 注意：前端类型检查必须用 `npx tsc -b --noEmit`（项目根 `tsconfig.json` 是 references 模式）。裸跑 `npx tsc --noEmit` 会读到根 `"files": []` 直接以 0 退出，**不检查任何文件**，是假通过。
