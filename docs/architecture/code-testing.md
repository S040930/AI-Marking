# AI 代码自动测试

## 工作流与证据

含代码作业会在 rubric 可信后进入代码测试节点。测试生成 agent 只接收题目 OCR 与服务端可信 rubric，不会收到学生代码、报告或数据集。它提交 1–20 个可复现的标准输入/输出测试项，服务端校验后保存为题目级草稿，并暂停 run 等教师预览。

教师可批准草稿，或要求重新生成。批准后，后续同题作业复用当前批准版本；教师也可在新 run 开始时选择重新生成。题目 PDF/OCR、可信 rubric 快照或执行策略版本改变时，旧测试集失效。每次 run 保存实际套件和逐项结果快照；评分 agent 只能引用服务端按 run、套件版本和原文结果核验过的测试证据。运行结果是辅助证据，教师仍检查代码与报告的一致性并确认最终成绩。

Notebook 文件不自动执行；每个测试项返回 `not_run`，不会成为 agent 可引用的测试证据。测试期望输出只留在宿主监督器，不会发送给学生程序；学生 stdin、stdout 与 stderr 通过监督器逐项传递和比较。

## 本机运行环境

代码执行支持 macOS Seatbelt，要求系统提供 `/usr/bin/sandbox-exec`，并安装以下精确运行时：

| 语言 | 固定运行时 | 定位方式 |
| --- | --- | --- |
| Python | 3.12.13 | Python base interpreter（不使用后端虚拟环境 shim） |
| R | 4.5.2 | 通过 `/usr/local/bin/Rscript` 定位版本；受限执行使用同一安装的 `R.home()/bin/exec/R` |
| Java | 11.0.28 | `/usr/libexec/java_home` 返回的 JDK，含 `java` 和 `javac` |

API 和批改 worker 启动时会检查 Seatbelt 可用性、版本和实际受限 profile：探针验证输入可读、工作目录可写、输入目录不可写、home 与 macOS 临时目录不可枚举、网络绑定与子进程启动受拒，并检查 Python、R `stats`/`utils`、Java 和 Javac 都能启动。自检失败时只禁用代码测试并记录原因；代码测试 fail-closed，不会改在普通宿主进程中运行。Notebook-only 作业不要求启动这些运行时。

Python 使用 `-s -S -B`，R 使用固定主程序和仅供启动的只读 profile，Java 使用固定 JDK；不会安装学生依赖。R profile 在默认包加载前将 `Sys.which` 设为空结果，避免 `utils`/`stats` 初始化时试图启动 `uname` 子进程；学生代码也不能通过 R 启动外部命令。profile 在独立 support 目录中，只读开放给该项运行。代码语言仅支持 Python `.py`、R `.r` 和 Java `.java` 控制台程序。每项测试都有独立工作目录，同题代码和数据集在输入目录只读暂存。

## Seatbelt 边界

每个测试项由可信宿主监督器启动 `/usr/bin/sandbox-exec`。profile 默认拒绝，允许固定解释器和运行时读取、该题输入读取、工作目录写入，拒绝网络，并不开放 `process-fork`。因此学生代码不能创建子进程或通过子进程脱离监督；编译与运行按顺序在各自受限进程中完成。Java 编译器和运行时也只在同一 profile 下启动。监督器不把测试期望值放进请求，且不受学生文件权限影响。

macOS 的系统运行时需要范围较宽的只读权限。profile 采用“宽读后收回”的策略：拒绝当前用户 home 和 `/private/var/folders`，然后只对运行时、输入目录和工作目录重新开放读取。写入仅开放工作目录，另允许 `/dev/null`。它不会像虚拟机那样提供独立内核或独立用户；`/private/tmp` 等其他可读系统路径仍可能被读取。因此结果标记为 `seatbelt:partial`，不能视为 Docker 或 VM 等价隔离。**该限制适用于可能恶意的学生代码；不要把这套运行器作为运行高风险未知程序的通用沙箱。**

## 资源与终止

| 边界 | 行为 |
| --- | --- |
| 网络 | Seatbelt 拒绝网络操作 |
| 子进程 | 不开放 `process-fork`；可执行路径使用固定清单，不设置独立线程数量上限 |
| 文件写入 | 仅每测试项工作目录；单文件 `RLIMIT_FSIZE` 为 256 MiB |
| 内存 | 每 100ms 通过系统进程表采样 RSS；超过 1 GiB 时终止。它是采样阈值，不是硬配额 |
| 工作目录 | 每 500ms 统计大小与条目；超过 256 MiB 或 10,000 个条目时终止。采样间隔内可能短暂越限 |
| 文件描述符 | 每个学生进程最多 256 个打开文件描述符 |
| CPU 与时间 | `RLIMIT_CPU` 作为补充；单项墙钟上限 10 秒，每份作业最多 180 秒。不提供 vCPU 硬配额 |
| 输出 | stdout 与 stderr 合计最多 16 KiB；超过后终止 |
| 测试规模 | 每份批准测试集最多 20 项；worker 并发 1 |

资源监督器与学生程序分开运行，流式读取 stdout/stderr，避免无界内存缓冲。取消、超时、内存、磁盘或输出超限会终止当前 sandbox-exec 进程。系统限制不允许学生代码创建子进程；若沙箱或监督器无法启动，整次代码测试按基础设施错误失败。

源代码最多约 100 MiB、数据集最多约 100 MiB；数据集按 1 MiB 块复制一次并校验 SHA-256，不整体载入内存。每次作业的基础暂存上限约 200 MiB，另加串行单项工作目录最多约 256 MiB；测试工作目录在本项结束后删除。内存由运行进程的采样 RSS 监测，预期单项上限约 1 GiB；短暂峰值可能超过阈值后才被终止。

测试集版本保存在 `code_test_suites`，实际套件和结果快照保存在 `grading_run_artifacts`。源码与输入数据不传给测试生成 agent，预期输出不传给学生程序；学生 stdout/stderr 按结果长度限制后保存。
