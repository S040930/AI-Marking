## 背景

mcp SDK 当前最新版就是 **2.0.0**，而项目依赖声明（`backend/pyproject.toml:26`、`requirements-dev.txt:730`、`requirements-prod.txt:684`）**早已锁定 `mcp==2.0.0`**。真正的问题有两个：

1. `backend/app/mcp/server.py` 仍用 1.x 旧 API `from mcp.server import MCPServer`；在 mcp 2.x 中 `MCPServer` 已不存在（降级为 `mcp.server.lowlevel.server.Server`，被 `FastMCP` 取代），导致 `tests/test_mcp_server.py` 收集时 `ImportError`。
2. 本地运行环境实际装的还是 **mcp 1.28.1**，与 requirements 锁定的 2.0.0 不一致。

`backend/app/mcp/` 全部为 git 未跟踪文件（含 server.py、api/mcp.py、schemas/mcp.py、models、tests、alembic 迁移），属于 Codex MCP 工作流整体待提交的一部分。

## 已确认的兼容性（读本机已装 SDK 源码核实）

- `FastMCP.__init__` 参数 `name` / `instructions` / `lifespan` 均存在，lifespan 语义兼容当前 `mcp_lifespan`。
- `FastMCP.tool(..., annotations=ToolAnnotations(...))` 签名不变；`ToolAnnotations` 在 2.x 仍在 `mcp/types.py`（模块文件而非包目录，但 `from mcp.types import ToolAnnotations` 依旧可用），字段 `readOnlyHint`/`destructiveHint`/`idempotentHint` 均保留。
- `FastMCP.prompt()` 签名 `(name, title, description, icons)`，裸 `@prompt()` 用法兼容。
- `FastMCP.run()` 默认 transport 为 `"stdio"`，内部走 `run_stdio_async()` + `stdio_server()`，与当前 `scripts/run-ai-marking-mcp` 的 `python -m app.mcp.server` 启动方式完全匹配，启动脚本无需改动。
- `server.py` 中 `MCPServer` 仅有一处实例化，无子类继承；`mcp_lifespan` 的类型注解需同步更新。

## 改动清单

### 1. `backend/app/mcp/server.py`（迁移到 mcp 2.x FastMCP）
- 第 16-17 行：`from mcp.server import MCPServer` → `from mcp.server import FastMCP`；`from mcp.types import ToolAnnotations` 保留不动。
- 第 54-78 行：
  - `mcp_lifespan` 类型注解 `_server: MCPServer` → `_server: FastMCP`
  - `mcp = MCPServer("ai-marking", instructions=..., lifespan=mcp_lifespan)` → `mcp = FastMCP("ai-marking", instructions=..., lifespan=mcp_lifespan)`
- 其余（5 个 `@mcp.tool` 装饰器、`@mcp.prompt()`、`main()` 里的 `mcp.run()`）**全部不用动**。

### 2. 环境升级到 2.0.0
- 激活后端虚拟环境，`pip install mcp==2.0.0 mcp-types==2.0.0`（或 `pip install --require-hashes -r requirements-dev.txt`）。
- 升级后用 `python -c "import app.mcp.server"` 验证 import 不再报错。

### 3. 测试
- 跑通 `backend/tests/test_mcp_server.py`（原先因 ImportError 无法收集的 6 个测试，import 修复后应恢复）。
- 跑全量后端 `python -m pytest tests/ -q` 与 `ruff check`，确保无回归。

### 4. 验证（无头环境能做到的边界）
- `scripts/run-ai-marking-mcp` 的启动链路（`python -m app.mcp.server` → `mcp.run()` stdio）无法在本环境端到端跑通（需要 Codex 客户端实际调用），只验证到"模块可 import + 6 个单测通过 + mcp 2.x FastMCP 能构建并注册 5 工具 1 prompt"这一层。真正的端到端由你本机 `./scripts/setup-codex-mcp --doctor` + 启动 Codex 验证。

## 明确不做

- **不**把 `mcp==2.0.0` 改成别的版本（它已是最新稳定版，且锁版本是防漂移的正确做法）。
- **不**处理 `backend/app/mcp/` 整个目录未跟踪的问题（提交与否由你决定，不属本次迁移范围）。
- **不**改任何 HTTP API、数据库、前端代码；迁移纯属本地 STDIO 客户端内部实现，对外行为零变化。
